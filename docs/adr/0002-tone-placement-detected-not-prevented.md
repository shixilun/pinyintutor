# Let users mis-place tone marks; detect the mistake, don't prevent it

The entry box applies a typed tone digit live to whichever letter sits immediately before the cursor, with no correctness check at keystroke time — so a user can type "líu" when the correct spelling is "liú". This looks like it contradicts ADR 0001 ("never display non-canonical forms"), but it doesn't: which vowel takes the tone in a compound final (iu, ui, etc.) is itself part of what this tutorial teaches, so letting the mistake be typed and then explained is the pedagogical point, not a gap to close. Correctness is detected rather than prevented: the syllable is round-tripped through `splittone()` (extract letters + tone index from wherever the diacritic sits) and `addtone()` (reapply the tone canonically); if the round trip doesn't reproduce the original string, the tone was on the wrong vowel, and that specific hint fires.
